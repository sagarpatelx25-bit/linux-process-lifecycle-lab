# Section 6: POSIX Process Signals & Asynchronous Notification

Signals are asynchronous notifications sent by the Linux kernel to a process to inform it of an event or request termination.

---

## 1. Common POSIX Signals

| Signal Number | Symbolic Name | Default Action | Description & Keyboard Trigger |
|---|---|---|---|
| `1` | `SIGHUP` | Terminate | Hangup detected on controlling terminal. |
| `2` | `SIGINT` | Terminate | Terminal interrupt signal generated by typing `Ctrl+C`. |
| `3` | `SIGQUIT` | Terminate & Core Dump | Terminal quit signal generated by typing `Ctrl+\`. |
| `9` | `SIGKILL` | Unconditional Kill | Immediately terminates the process; **cannot be caught, blocked, or ignored**. |
| `11` | `SIGSEGV` | Terminate & Core Dump | Invalid memory access (Segmentation Violation). |
| `15` | `SIGTERM` | Terminate | Standard software termination request; can be handled for graceful shutdown. |
| `19` | `SIGSTOP` | Stop Process | Pauses execution; **cannot be caught or ignored** (`Ctrl+Z` sends `SIGTSTP`). |
| `18` | `SIGCONT` | Continue | Resumes execution of a previously stopped process. |

---

## 2. Catching Signals in C

Using the `signal()` or POSIX `sigaction()` system call:

```c
#include <signal.h>

void handler(int signum) {
    // Perform cleanup before exiting
}

signal(SIGINT, handler);
```
